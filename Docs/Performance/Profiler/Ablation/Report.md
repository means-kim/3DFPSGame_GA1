# 최적화 2단계: 병목 분석 (2026-11-03)

1단계 기준 측정(`../Baseline/Report.md`)에서 꼽은 후보를 **하나씩 끄고** 같은 Play 세션 안에서 측정했다. 실제 최적화가 아니라 "이것을 없애면 얼마나 줄어드는가"를 재는 실험이다. 실험 뒤 모든 설정은 원래 값으로 복구했다.

## 측정 방법
- 시점 A~D(1단계와 같음), 설정마다 30프레임을 버리고 300프레임의 **중앙값**을 기록했다.
- Profiler 녹화(GPU 포함, 에디터 제외)를 켜 둔 1단계와 같은 조건이다.
- 기준 상태(`base`)를 처음, 중간, 끝에 세 번 측정해 측정 간 흔들림을 확인했다.
- 원본: `ablation.json`(후보별), `ablation_extra.json`(렌더 스케일 0.5, 후보 일괄 끄기)

| 설정 | 내용 |
|---|---|
| probes_off | 반사 프로브 4개 끔 |
| shadow_dist_50 | 그림자 거리 80 → 50 m |
| cascade_2 | 그림자 cascade 4 → 2 |
| katana_shadow_off / katana_off | 카타나(500k tris)의 그림자만 끔 / 렌더러 끔 |
| minimap_shadow_off / minimap_off | 미니맵 카메라의 그림자만 끔 / 카메라 끔 |
| ssao_off | SSAO 렌더러 피처 끔 |
| post_off / bloom_off / grain_off | 포스트 프로세싱 전체 / 블룸 / 그레인 끔 |
| render_scale_05 | 렌더 해상도 절반(A, C만) |
| all_off | 미니맵 끔 + SSAO 끔 + 포스트 끔 + cascade 2 + 카타나 그림자 끔(A, C만) |

## 측정 오차
기준 상태 세 번의 범위는 다음과 같다(`base`/`base2`/`base3`).

| 시점 | GPU | CPU Main |
|---|---|---|
| A | 6.50 ~ 7.00 ms | 2.65 ~ 3.01 ms |
| B | 7.11 ~ 7.40 ms | 2.60 ~ 2.65 ms |
| C | 6.64 ~ 6.75 ms | 2.85 ~ 2.92 ms |
| D | 6.97 ~ 7.10 ms | 2.89 ~ 3.03 ms |

**GPU는 약 ±0.3 ms, CPU Main은 약 ±0.2 ms 안의 변화는 의미가 없다.** Batches, SetPass, Triangles, Shadow Casters는 매번 정확히 같아서 오차가 없다.

## 결과 1: GPU 시간은 어떤 후보로도 줄지 않는다

| 시점 | base | probes_off | katana_off | minimap_off | ssao_off | post_off | render_scale_05 | all_off |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| A | 6.50~7.00 | 7.08 | 6.88 | 5.97 | 6.86 | 6.61 | 7.85 | 7.65 |
| C | 6.64~7.09 | 6.91 | 7.17 | 6.14 | 6.95 | 7.09 | 7.30 | 7.43 |

(단위 ms)

- **반사 프로브를 꺼도 GPU 시간이 그대로다.** 1단계에서 `UpdateReflectionProbeAtlas`가 7~8 ms로 집계된 것은 집계 착시로 확인되었다. 프로브는 최적화 대상에서 제외한다.
- 삼각형을 2.4M → 0.4M으로 줄여도(`katana_off`), **해상도를 절반으로 낮춰도**(`render_scale_05`), 후보를 한꺼번에 꺼도(`all_off`) GPU 시간이 약 7 ms에서 내려가지 않는다.
- 따라서 이 약 7 ms는 장면을 그리는 비용이 아니다. 에디터 환경에서 장면 내용과 무관하게 잡히는 바닥값(에디터 화면 갱신, 프레임 간격 등)으로 판단한다. **에디터에서는 GPU 병목을 판정할 수 없다.** 실제 GPU 비용은 Development Build에 Profiler를 붙여야 알 수 있다.
- 미니맵을 끄면 A, C, D에서 0.4~0.5 ms 줄어드는 경향은 있다. 다만 B에서는 줄지 않아 오차와 구분하기 어렵다.

## 해석
1. **미니맵 카메라가 CPU 비용 1순위다.** 끄면 모든 시점에서 CPU Main이 0.5~0.8 ms(약 25%), Render Thread가 0.3 ms 줄고 SetPass가 16개 준다.
   - 512×512 직교 카메라인데 **그림자를 그리고**(`renderShadows = true`), Culling Mask도 넓다.
   - 미니맵은 그림자가 필요 없다. 그림자만 꺼도 Shadow Casters가 약 100개 준다.
2. **SSAO가 Batches의 약 1/3을 만든다.** 끄면 Batches가 84~127개, 삼각형이 0.6M 줄어든다.
   - 현재 설정은 `Source: DepthNormals`다. 노멀을 얻으려고 장면 전체를 한 번 더 그리는 사전 패스(Depth Normals Prepass)가 생긴다.
   - `Source: Depth`로 바꾸거나 `Downsample`을 켜면 화질을 크게 해치지 않고 비용을 줄일 여지가 있다.
3. **cascade 4 → 2**: Shadow Casters가 25~40%, 삼각형이 0.5M 준다. 다만 원거리 그림자 품질이 떨어지므로 3단계에서 화면을 보고 판단해야 한다(cascade 3이 절충안).
4. **카타나**: 삼각형 수의 대부분(근거리 2.0M 중 1.0M이 그림자)을 차지한다. 그런데 GPU 시간에는 변화가 없었다. 에디터 측정의 한계 때문일 수 있다. 저사양 대상이라면 메시 데시메이션이 근본 해결책이다.
5. **효과 없음**:
   - 반사 프로브, 블룸, 그레인은 효과가 없다.
   - 포스트 프로세싱 전체를 꺼도 SetPass만 17개 줄고 시간 변화는 없다.
   - 그림자 거리 50 m는 오히려 A에서 삼각형이 늘었다. cascade 경계가 당겨져 카타나가 더 많은 cascade에 들어가기 때문이다. 되돌릴 이유가 없다.
6. 가장 큰 후보를 모두 끈 `all_off`에서도 CPU Main 감소는 1.0 ms(약 35%)다. **게임은 이미 가벼운 편이다.** Profiler에서 보이는 약 10 ms 프레임 시간의 대부분은 에디터 오버헤드(`EditorLoop` 약 7 ms)다.

## 3단계 최적화 제안 (효과 대비 부작용 순)
1. **미니맵 카메라**
   - 그림자를 끈다(`renderShadows = false`). 화면 영향이 거의 없다.
   - Culling Mask를 지형, 건물 등 필요한 레이어로 줄인다.
   - 필요하면 갱신 주기를 매 프레임에서 2~3프레임에 한 번으로 낮춘다(스크립트 변경 필요).
2. **SSAO 설정 조정**: `Source: Depth` 또는 `Downsample` 켬. 전후 화면 비교로 화질을 확인한다.
3. **그림자 cascade 4 → 3(또는 2)**: 화면 비교 후 결정한다.
4. (선택) 카타나 그림자 끄기 또는 메시 데시메이션
5. (검증) Development Build + Profiler 연결로 실제 GPU 비용 측정
