# 태양 렌즈 플레어 적용 리포트 (2026-11-02)

노을 역광 분위기를 살리려고 Sun(Directional Light)에 URP 렌즈 플레어(SRP)를 붙였다.

## 변경 내역
- `Assets/09.Materials/LensFlare/SunsetSunFlare.asset`
  - URP 기본 플레어(`Default Lens Flare (SRP)`)를 복제한 뒤 색을 노을용으로 바꿨다.
  - 요소 7개: 태양 주변 큰 글로우 1개, 고스트 6개.
  - 원본의 초록·파랑 계열 고스트를 주황·호박색 계열로 변경했다.
  - 고스트 세기를 원본의 2.5배로 올렸다. 원본 세기로는 화면에서 거의 보이지 않았다.
  - 가로로 길게 퍼지는 빛줄기(아나모픽 스트릭)도 시도했지만, 건물 위에 주황 띠가 걸쳐 보여 뺐다.
- `GameScene.unity`: 루트 `Directional Light`에 `LensFlareComponentSRP`를 추가했다.
  - 세기 1.2, 가림(Occlusion) 켬, 샘플 32, 화면 밖 허용 끔.

## 측정 방법
`../PointLight_ShadowDistance/Report.md`와 같다. 태양이 보이는 시점 H(정면)와 I(화면 가장자리)를 추가했다.
- **Stats:** Play 모드, timeScale 0, 고정 시점에서 Game 뷰 Stats를 화면 캡처했다(A~D, H).
- **화면:** 에디터 오프스크린 카메라로 렌더링했다(A~D, H, I).
  - 렌즈 플레어의 가림 판정은 이전 프레임 결과를 쓴다. 그래서 시점마다 두 번 렌더링해 두 번째 결과를 저장했다.

## 해석
1. **태양이 화면에 없을 때(A~D)는 비용이 없다.** Batches와 SetPass 차이는 ±4 안의 측정 오차다.
2. **태양이 보일 때(H)는 Batches와 SetPass가 각각 약 23 늘어난다.**
   - 플레어 요소마다 별도의 패스로 그리기 때문이다. 고스트는 여러 개씩 복제되므로, 요소 7개가 약 23번의 그리기가 된다.
   - CPU 시간 차이(+0.2ms)는 오차 범위 안이다.
   - 최적화 단계에서 줄이려면 고스트 개수(`count`)를 줄이거나, 거의 보이지 않는 요소 5~6번을 빼면 된다.
3. **가림 판정이 동작한다.** 태양이 건물 뒤에 있는 시점에서는 플레어를 켜도 화면 밝기가 변하지 않았다. 보이는 시점(H)에서는 평균 밝기가 +0.014 올랐다.
4. **화면:**
   - 태양 주변에 따뜻한 빛 번짐이 생겼다.
   - 태양과 화면 중심을 잇는 선을 따라 호박색 고스트가 보인다(H, I).
   - 태양을 화면 가장자리에 두면(I) 고스트가 반대편으로 흩어져 렌즈 느낌이 난다.

## 남은 과제
- 플레어 세기는 컴포넌트의 `intensity`(현재 1.2) 하나로 조절할 수 있다.
- 플레이 중 카메라를 움직일 때 깜빡임이 없는지는 Play 모드에서 직접 확인이 필요하다.
